## 概念速查框

> 本节供不熟悉技术背景的读者速查，读懂这些概念后阅读后续各册将无障碍。

| 术语 | 通俗解释 |
|---|---|
| **Agent（智能体）** | 一个有"职务"的 AI 角色，例如"创意总监"或"QA 工程师"。每个 agent 有一份说明书（`.md` 文件），告诉 AI 它的职责、权限和工作方式。 |
| **Skill（技能/斜杠命令）** | 用户输入 `/brainstorm` 或 `/dev-story` 等命令时触发的工作流程序。类似给 AI 一份"操作手册"，告诉它按什么步骤完成某件事。 |
| **Hook（钩子/触发器）** | 一段在特定事件发生时自动运行的脚本，例如"每次提交代码前检查是否有硬编码数值"。类似门卫，在关键操作前后自动执行检查。 |
| **Rule（规范/规则）** | CCGS 中：作用于特定目录的编码或文档标准（例如"`src/gameplay/` 下不能硬编码数字"），AI 编辑该目录文件时自动参照。**注意**：CodeBuddy 的 Rule 不支持路径作用域，详见 01b 册 P1。 |
| **Frontmatter（文件头声明）** | 文件最顶部的 YAML 格式配置块（两行 `---` 之间的内容），相当于文件的"身份证"，记录 name/model/tools 等元数据。 |
| **YAML** | 一种用缩进表示层级结构的配置文件格式（`.yaml`/`.yml`），类似 JSON 但更易人工阅读。 |
| **Bash / Shell 脚本** | Linux/Mac/Git Bash 下的命令行程序（`.sh` 文件），Hook 基本都用它编写。 |
| **Tier（层级）** | CCGS 中 agent 按能力分三层：Tier 1（总监级，用最强模型 Opus）→ Tier 2（部门负责人，Sonnet）→ Tier 3（专员，Sonnet/Haiku）。 |
| **Director Gate（总监关卡）** | 工作流中需要特定总监级 agent 审核才能通过的检查点，例如"创意总监批准概念才能进入下一阶段"。 |
| **Pipeline（流水线）** | 指游戏开发的完整阶段链条：概念 → 系统设计 → 技术搭建 → 预制作 → 生产 → 打磨 → 发布，共 7 个阶段。 |
| **ADR（架构决策记录）** | Architecture Decision Record，一份记录"为什么做了这个技术选择"的文档，方便日后追溯。 |
| **GDD（游戏设计文档）** | Game Design Document，描述某个游戏系统（例如战斗系统）的完整设计规格文档。 |
| **MVP（最小可行产品）** | Minimum Viable Product，指优先级最高、必须先实现的核心功能集合。 |
| **Spawn（生成/调用子智能体）** | 在一个 skill 或 agent 运行过程中，调用另一个 agent 来完成某个子任务，类似"老板把任务分派给下属"。 |
| **Claude Code** | Anthropic 出品的命令行 AI 编程工具，CCGS 整个框架就是为它设计的。 |
| **CodeBuddy** | 腾讯出品的 AI 编程助手（本工作室的目标平台），本报告的移植建议就是从 Claude Code → CodeBuddy。 |
| **配置目录差异** | CCGS 用 `.claude/`，CodeBuddy 用 `.codebuddy/`。两者目录结构高度相似（settings.json/agents/skills/rules 等），是移植中最直观的对应关系。后续报告中两者会交替出现。 |
