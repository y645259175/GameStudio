## 1. 灵根系统（修仙资质起点）

### 1.1 设计精神

> 用户定调（2026-05-26）：
> - 五行系统（金 / 木 / 水 / 火 / 土）+ 兼容变异灵根
> - 灵根是 5 个值，每个 0-100，总和 ≤ 100（鬼谷八荒式）
> - 同灵根之间有质量差异（数值大小决定）
> - 灵根**通过功法系数**影响修炼速度，不是直接固定
> - 门主与弟子灵根分布无系统性区别（看招收 / 生成系统）

### 1.2 数据结构（M3 实现 · 用户定调 v2 离散点数 + 无硬上限）

```gdscript
# SpiritRoot.gd（数据类）
class_name SpiritRoot

var roots: Dict = {
    "metal": 0,    # 金 整数点数
    "wood":  0,    # 木
    "water": 0,    # 水
    "fire":  0,    # 火
    "earth": 0,    # 土
    # 变异灵根预留扩展（M3 不启用，但 schema 支持）：
    # "thunder": 0,  # 雷
    # "wind":    0,  # 风
    # ...
}

# 约束：
# - 单元素 ∈ [0, ∞)（无硬上限）
# - 初始随机生成时总和 ≤ 10（生成系统约束，非数据约束）
# - 运行时总和无上限（可通过血脉 / 丹药 / 顿悟 / buff 等突破 10）
```

> **关键设计哲学**（用户定调 v2）：
> - "10" **不是硬上限**，是**初始随机化上限**——平民起点
> - 后续可通过多种渠道突破 10：血脉天赋、洗髓丹、顿悟事件、突破副产物、临时 buff
> - 单元素也**无任何上限**——理论上"火 100"是可能的（顶级老怪物）
> - 这给游戏长线天花板感：10 是起点，不是终点

### 1.4 灵根成长渠道（M3 vs 后续）

| 渠道 | 实现方式 | M3 是否启用 | 备注 |
|---|---|---|---|
| **初始随机生成** | 角色生成系统：随机分配 0-10 总点数到五行 | ✅ M3 | 平民起点 |
| **血脉天赋**（如赤焰血脉初始火 +5）| Character 加 `bloodline_id` 字段；生成时叠加血脉模板 | ⏳ 后续 | M3 schema 预留 `bloodline_id: String = ""` |
| **临时丹药**（短期 +N 灵根）| buff 系统 `cultivation/root_boost`，attributes = `{element, amount}`，时长 1-N 月 | ⏳ 后续（buff 框架 M3 已支持）| 不修改 base_roots，运行时累加 |
| **永久强化**（洗髓丹 / 顿悟）| `SpiritRootService.adjust_base_root(character, element, delta)` 直接改 base 值 | ⏳ 后续 | M3 提供 API 即可，玩法 M5+ |
| **境界突破副产物** | 突破时按概率 / 必然 +1 某灵根 | ⏳ 后续 | GDD-04 平衡时定 |

#### 临时 vs 永久的存储分离（关键架构）

```
有效灵根值（effective_root）= base_root + Σ(active root_boost buff attributes)

base_root: SpiritRoot.roots[element]              # 永久值，存档
buff 加成: BuffService.sum_attribute(
              character, "cultivation", "root_boost",
              attr_filter = {"element": element})
```

这样：
- **永久强化**（洗髓丹）= `adjust_base_root()` 修改 `SpiritRoot.roots[element]`
- **临时强化**（短期丹药）= `BuffService.apply_by_id("buff_root_boost_fire_3m", character)`
- **查询有效值**：永远走 `SpiritRootService.get_effective_root(character, element)`
- buff 失效不会污染永久数据；永久强化不依赖 buff 存活

> 这正是 §6.10 buff 系统"修饰器"哲学的标准应用——临时增益走 buff，永久属性走 base 字段。

### 1.5 杂质语义（用户定调 v1 · B 无影响 / 不变）

总和 < 当前上限 = 空闲容量，**无任何运算影响**。

| # | 候选 | 杂质效果 | 结论 |
|---|---|---|---|
| A | 普惠速度扣减 | 总速度 × (1 - 杂质% × k) | ❌ 放弃 |
| **B** | **无影响（空容量）** | 不参与任何计算 | ✅ 选择 |
| C | 杂质 = 体质 / 寿元加成 | 杂质多换其他属性 | ❌ 放弃 |

**B 的设计含义**（v2 离散版本下）：
- 角色强弱由"**灵根总量 + 灵根分布 + 功法匹配**"三者综合决定
- "火 3 单灵根"角色配纯火功法可能比"五行各 2 杂灵根"更快（见 §1.6 示例）
- 玩家在弟子招收 / 培养时有真实策略选择
- 不需要"洗髓丹消除杂质"机制（永久强化是"加值"，不是"消杂质"）

### 1.6 修炼速度公式（用户定调）

```
单功法修炼速度 = base_speed × (1 + Σ aᵢ × effective_rootᵢ)

其中：
- base_speed: 该功法的基础速度（功法等级 / 境界相关）
- aᵢ: 该功法定义的 i 灵根加成系数（在功法数据中）
- effective_rootᵢ: 角色 i 灵根有效值 = base + buff_boost（见 §1.4）
- 单功法所有系数之和（Σa）约束在 0.05 ~ 0.20（详见 §1.7）
```

#### 设计示例（v2 离散点数）

> 示例假设角色全是初始生成（无 buff 增益），effective = base

| 功法 | 灵根系数 | 角色 1 (火 10) | 角色 2 (火 5 水 5) | 角色 3 (五行各 2) | 角色 4 (火 3 单灵根) |
|---|---|---|---|---|---|
| 纯火 | a_fire=0.08 | 1 + 0.80 = **1.80** | 1 + 0.40 = **1.40** | 1 + 0.16 = **1.16** | 1 + 0.24 = **1.24** |
| 火土双修 | a_fire=0.05, a_earth=0.03 | 1 + 0.50 = **1.50** | 1 + 0.25 = **1.25** | 1 + 0.10+0.06 = **1.16** | 1 + 0.15 = **1.15** |
| 通用 | 五行各 0.02 | 1 + 0.20 = **1.20** | 1 + 0.20 = **1.20** | 1 + 0.20 = **1.20** | 1 + 0.06 = **1.06** |

> **关键观察**：
> 1. 通用功法下，角色 1/2/3 速度完全一样（总点数都是 10）→ 灵根总量决定通用功法上限
> 2. 纯火功法下角色 4（火 3 单灵根）比角色 3（杂灵根 5×2）更快 → §1.5 B 的"总量 + 匹配双驱动"印证
> 3. 灵根分布决定"专精 vs 广度"的策略选择

#### 高境界数值膨胀的设计意图（用户认可的修仙感）

随着血脉觉醒 / 丹药 / 突破副产物累计，老怪物可能"火 50"甚至"火 100"：

| 功法 | 老怪物 (火 50) | 凡品 (火 10) | 速度比 |
|---|---|---|---|
| 纯火 a=0.08 | 1 + 4.00 = **5.0x** | 1.80x | ~2.8 倍 |
| 纯火 a=0.10 | 1 + 5.00 = **6.0x** | 1.90x | ~3.2 倍 |

> 设计认可这种"老怪物碾压凡人"的修仙感，**数值膨胀是修仙世界观的真实表达**，不是 bug。
> 战斗中 1 大境界差通常导致 5-10 倍数值差距（GDD-04 / 战斗系统具体平衡）。

### 1.7 平衡假设（落 GDD-04 详细数值）

- 单灵根系数 a 一般在 0.01 ~ 0.10 区间
- 单功法所有系数之和（Σa）建议在 0.05 ~ 0.20，避免低境界速度过分膨胀
- 顶级 / 专精功法可能更高系数（如 a_fire=0.12），但有门槛限制（如要求某灵根 base ≥ 8）
- 通用功法系数低且广（如示例 五行各 0.02），适合杂灵根 / 早期弟子保底

### 1.8 数据驱动落地

| 表 | 路径 | 内容 |
|---|---|---|
| 元素类型 | `data/elements/element_types.tres` | 见 §1.3 |
| 功法定义 | `data/cultivation_methods/*.tres` | 含 `root_coefficients: Dict[element_id, float]` 字段 |
| 角色生成模板 | `data/character/templates/*.tres` | 灵根分布权重（见 §5 弟子招收）|
| 血脉模板（后续）| `data/bloodlines/*.tres` | 血脉名 + 灵根加成 + 描述 |
| 灵根 buff 类型（后续）| `data/buffs/cultivation/root_boost.tres` | 临时灵根增益 buff |

### 1.9 实现要点

- `SpiritRoot.gd` 数据类（含 `roots: Dict[String, int]` + 序列化）
- `SpiritRootService.gd`（autoload 或合并到 CharacterService）：
  - `get_base_root(character, element_id) -> int`
  - `get_effective_root(character, element_id) -> int`（含 buff 加成）
  - `get_total_base(character) -> int`（基础灵根总和）
  - `adjust_base_root(character, element_id, delta, reason)`（永久变更）
  - `calculate_cultivation_speed(character, method) -> float`
- 校验：
  - 所有 element_id 必须在元素表中注册
  - delta 操作不能让单元素值 < 0
  - 初始生成系统执行 sum ≤ 10 约束（运行时不约束）
- 单元测试覆盖：
  - 离散点数序列化 / 反序列化
  - effective = base + buff 加成计算
  - buff 失效后 effective 自动恢复（不污染 base）
  - 永久强化（adjust_base_root）独立于 buff
  - 修炼速度公式（示例 4 个角色 × 3 个功法 = 12 用例）
  - 未注册 element_id 报错
  - 初始生成 sum ≤ 10 约束

## 2. 境界系统（修仙等级表 + 突破张力）

### 2.1 设计精神

> 用户定调（2026-05-26）：
> - 5 大境 × 9 小境 = 45 层 + 飞升（结构）
> - 小境界满即升；大境界突破需要"满 + 条件 + 概率检定"
> - 突破概率是**动态累积**的（继续修炼提升）+ **多维度叠加**（基础 + 修炼 + 灵根 + 悟性 + 增益）
> - 寿元不外显，濒死提示；用完直接死亡
> - 突破失败 = 反向进度（跌 1 小境 + 修炼分清零）

### 2.2 境界结构（5 × 9 + 飞升）

| 大境界 | 小境界 | 寿元加成（基础 80-100，可配）| 进入门槛 |
|---|---|---|---|
| **凡人** | —（默认起点）| 50-70 年随机（约 600-840 月）| 出生 |
| **炼气** | 1-9 层 | +80-100 年 | 凡人觉醒 → 炼气 1 层 |
| **筑基** | 1-9 层 | +80-100 年 | 炼气 9 层 → 突破 |
| **金丹** | 1-9 层 | +80-100 年 | 筑基 9 层 → 突破 |
| **元婴** | 1-9 层 | +80-100 年 | 金丹 9 层 → 突破 |
| **化神** | 1-9 层 | +80-100 年 | 元婴 9 层 → 突破 |
| **飞升** | —（终极目标）| ∞ / 离场 | 化神 9 层 → 突破 |

> 寿元增加量每境单独可配（GDD-04 平衡专章设定），M3 默认 80-100 年区间随机。

#### M3 范围

玩家在 M3 单次循环（前期 20 min / 后期 60 min）能体验：
- 炼气小境界递进 1-3 次
- **可能** 1 次大境界突破（炼气 9 层 → 筑基 1 层），让玩家亲历"突破紧张感"
- 全游戏（M4-M7）终极目标：飞升

### 2.3 修炼值机制（小境界自动 / 大境界瓶颈）

```
小境界（1-8 层 → 下一层）
  修炼值满 → 自动升 → 修炼值清零

大境界 9 层 → 下一大境界 1 层
  修炼值满 → 进入"瓶颈"状态（不再自动升）
  此后每月修炼累积"修炼分"
  玩家可在任意时刻发起突破检定（满足条件后）
```

> "瓶颈"是行动状态 `IN_CULTIVATION` 的 mode 之一（详见 ADR-0003 state_data）。
> 玩家在瓶颈期可继续打磨提升概率，也可立即冲，是策略选择。

### 2.4 突破检定（用户定调 · 多维度概率公式）

#### 公式（v1 · 全参数可配）

```
最终突破概率 = clamp(基础概率 + 增益叠加, 0, 1)

────────────────────────────────────
基础概率
────────────────────────────────────
基础概率 = (基础分 + MAX(修炼分, 10) + 灵根分 + 悟性分) / 难度分

  基础分     = 该功法在该境界的"突破基础分"（功法 × 境界 表配置）
  修炼分     = 瓶颈后修炼月数 × 单月基础修炼分(全局) × 悟性/100
  灵根分     = Σ rootᵢ (i ∈ 功法绑定灵根)（简单和，整数）
  悟性分     = (悟性 - 100) / 10
  难度分     = 该功法在该境界的"难度系数"（功法 × 境界 表配置）

────────────────────────────────────
增益叠加（未来扩展 · buff 系统 / 道具系统）
────────────────────────────────────
+ 突破丹 / 道具 buff（如 `cultivation/breakthrough_aid`，临时 +X%）
+ 宗门 buff（如灵气浓郁间接通过修炼分加速）
+ 顿悟 / 特殊事件触发的临时 buff
+ 长老阁指点 buff
+ ...

────────────────────────────────────
上限处理
────────────────────────────────────
clamp 到 [0, 1]：≥ 1.0 即必成功；< 0 视为 0（基本不会发生）
（用户定调 A：无 95% 上限，允许玩家通过极致投入做到 100%）
```

#### 公式分项说明

| 分项 | 角色属性来源 | 系统/数据来源 | 设计意图 |
|---|---|---|---|
| **基础分** | — | 功法 × 境界 表 | 功法对该境界的"友好度"：高级功法基础分高 |
| **修炼分** | 悟性 | 瓶颈后月数 + 全局每月分 | 时间投入 + 悟性加成；瓶颈后越久越容易（递减由下面公式自然体现） |
| **MAX(修炼分, 10)** | — | 常量 10（可配）| **保底**：瓶颈一刻就能冲，0 月不被锁死 |
| **灵根分** | 灵根 | 功法绑定的灵根集合 | 修对了功法 → 灵根加成；选错功法 → 灵根无加成 |
| **悟性分** | 悟性 | (悟性 - 100) / 10 | 悟性 100 为基线（0 分），高悟性双重加成 |
| **难度分** | — | 功法 × 境界 表 | 该境界突破的总难度；高境界难度大幅上升 |

> **悟性的双重作用**（关键稀缺属性）：
> 1. 直接：`悟性分 = (悟性 - 100) / 10`
> 2. 间接：`修炼分 = ... × 悟性/100`
>
> 高悟性弟子 = 修炼快 + 突破快 + 概率累积快，是稀缺培养目标。

#### 设计示例（演算）

假设全局配置：
- 单月基础修炼分 = 5
- 某炼气 9 → 筑基 1 突破：基础分 = 20，难度分 = 100
- 角色：火 5 木 3（火木功法绑定）+ 悟性 = 120

| 场景 | 瓶颈后月数 | 修炼分计算 | 修炼分（MAX 后）| 公式 | 基础概率 |
|---|---|---|---|---|---|
| 刚到瓶颈即冲 | 0 | 0×5×1.2=0 | **10** | (20+10+8+2)/100 | **40%** |
| 打磨 3 月再冲 | 3 | 3×5×1.2=18 | **18** | (20+18+8+2)/100 | **48%** |
| 打磨 6 月 | 6 | 6×5×1.2=36 | **36** | (20+36+8+2)/100 | **66%** |
| 打磨 12 月 | 12 | 12×5×1.2=72 | **72** | (20+72+8+2)/100 | **102% → clamp 100%** |
| 同条件 + 突破丹（+20%）| 6 | 36 | 36 | 66% + 20% | **86%** |

> 这正是用户设计精神的具象化：**急于求成 40% 概率赌一波 / 稳扎稳打 12 月必成 / 丹药辅助居中**。

#### 突破触发条件（M3 简化 / 后续扩展）

- **M3**：满足修炼值满即可发起检定（消耗对应"基础道具"如 1 颗突破丹）
- **后续**：每个境界 × 功法可在表中配置必需道具列表 / 品质影响（如金丹突破需要"金丹基"，品质高基础分 +X）

### 2.5 突破失败惩罚（用户定调 · 反向进度）

突破失败：
- **境界跌 1 小境**（如金丹 9 层 → 金丹 8 层）
- **修炼分清零**（瓶颈后月数 = 0）
- **修炼值清零**（重新累积到 9 层瓶颈）
- 走火 buff（推荐，可选）：`injury/qi_deviation`，1-3 月不能修炼 + 修炼速度 -50%
  - M3 可选实现；至少要有反向进度

> 设计含义：失败不是灾难（不掉大境），但意味着"重新打磨上去 + 重新冲"——时间代价真实存在。
> 配合"修炼分递减归 0"，玩家失败一次后下一次冲的概率从头算，不能"前期失败白嫖修炼分"。

### 2.6 寿元规则（用户定调 · A 实数月 + C 不外显 + 个体差异）

#### 数值规则

| 阶段 | 寿元加成 | 配置 |
|---|---|---|
| **凡人起点** | 50-70 年随机（600-840 月）| 上下限可配置 |
| **炼气** | +80-100 年（960-1200 月）| 每境单独配置 |
| **筑基** | +80-100 年 | 同上 |
| **金丹** | +80-100 年 | 同上 |
| **元婴** | +80-100 年 | 同上 |
| **化神** | +80-100 年 | 同上 |
| **飞升** | ∞ / 离场 | 终极目标 |

> 注：寿元加成默认 80-100 是 M3 占位，实际数值由 GDD-04 平衡专章决定。
> 修仙小说常见"金丹 +500 年 / 元婴 +1500 年"等阶梯式跳跃，未来可调。

#### 寿元修饰渠道（数据驱动 · 通过 buff 系统）

寿元支持外部影响，通过 buff 系统统一：

| buff 类型 | 效果 | 来源 |
|---|---|---|
| `lifespan/longevity_bloodline` | 永久 +X 月 | 血脉天赋（生成时挂） |
| `lifespan/elixir_extension` | 永久 +X 月（消耗道具）| 服用延寿丹 |
| `lifespan/forbidden_art` | -X 月 + 战力提升 | 修炼禁术 / 燃血秘法 |
| `lifespan/cursed` | 持续 / 永久 -X 月 | 中诅咒 / 寿元被夺 |

> 这些 buff M3 不一定全实现，但 buff 系统已支持，后续按需添加。

#### UI 显示（关键设计点 · 不外显）

- **平时**：寿元不在 UI 显示具体数字
- **濒死警告**：当剩余寿元 < 50 月，状态栏出现"寿元将近"提示
- **死亡触发**：剩余寿元 = 0 时角色自动 `ActionState → DEAD`

> 设计含义：避免玩家盯着数字精算"还能闭关几月" → 修仙者的"感觉自己还能活很久"——直到某天"寿元将近"敲门。
> 玩家此时被迫做决策：突破 / 服延寿丹 / 传位 / 安排后事。

### 2.7 寿元终结与游戏结束条件（用户定调）

#### 寿元用完处理

- 角色（包括门主 / 弟子 / 长老 / NonSect）寿元 → 0：
- 直接 `ActionState → DEAD`（无"坐化事件" / 无"传位机会"）
- 这是**强制终态**——玩家必须在濒死警告期间主动处理

#### 游戏结束条件

> 用户定调："如果门派没有一个人则游戏结束"

游戏结束触发：
```
all([member.action_state == DEAD for member in sect.members]) == True
→ 触发 GameOver
```

- 包括门主 + 所有弟子 + 所有长老都死亡
- 中间任意时刻满足条件即触发
- M3 实现：简单 GameOver 界面（玩家可选"读档" / "退出"）
- M5+ 可扩展：游戏结束总结 / 主线大事记回顾 / 时代评价

### 2.8 数据驱动落地

| 表 | 路径 | 内容 |
|---|---|---|
| 全局突破常量 | `data/cultivation/breakthrough_constants.tres` | 单月基础修炼分 / MAX 保底 / 失败惩罚等级 / 寿元上下限 |
| 境界定义 | `data/cultivation/realms.tres` | 5 大境 × 9 小境 + 每境寿元增加上下限 |
| 功法 × 境界突破表 | `data/cultivation_methods/<method>.tres` 内 `breakthrough: { realm_id: {base_score, difficulty_score, required_items} }` | 每个功法在每个境界的基础分 / 难度分 / 必需道具 |
| 寿元修饰 buff | `data/buffs/lifespan/*.tres` | 长寿血脉 / 延寿丹 / 禁术 / 诅咒等 |
| 增益 buff | `data/buffs/cultivation/breakthrough_aid.tres` | 突破丹临时 buff |

### 2.9 实现要点

- **数据类**：
  - `Realm.gd`（大境界 / 小境界数据）
  - `BreakthroughAttempt.gd`（一次突破检定的快照：公式输入 / 结果 / reason）
- **服务类**：
  - `CultivationService.gd` autoload
    - `get_realm(character) → Realm`
    - `add_cultivation_value(character, delta)`（修炼值累积，满即升小境 / 进入瓶颈）
    - `is_at_bottleneck(character) → bool`
    - `get_bottleneck_months(character) → int`
    - `calculate_breakthrough_probability(character, method) → float`（执行公式）
    - `attempt_breakthrough(character, method, items) → BreakthroughResult`
- **修炼分计数**：
  - 进入瓶颈时初始化 = 0
  - 每月 TimeService.month_advanced + IN_CULTIVATION 时 +1
  - 突破失败时清零
  - 历练 / 其他行动状态时**不+但不清零**
- **寿元服务**：
  - `LifespanService.gd` autoload（或合并 CharacterService）
    - `get_remaining(character) → int`（含 buff 加成）
    - `tick_monthly(character)`：每月 -1
    - 监控 < 50 月 → 触发"寿元将近" UI signal
    - 监控 = 0 → 触发 `CharacterService.set_action_state(c, DEAD, "lifespan_zero")`
- **游戏结束监听**：
  - `GameOverService.gd` autoload
  - 订阅 `CharacterService.action_state_changed` signal
  - 任一角色死后检查 sect 全员状态
  - 全死 → 触发 GameOver
- **单元测试覆盖**：
  - 修炼值满 → 自动升小境
  - 修炼值满 9 层 → 进入瓶颈（不自动升）
  - 瓶颈后月数计数正确（含历练暂停 / 失败清零）
  - 突破概率公式 5 个场景（见 §2.4 示例表）
  - 突破成功 → 大境界进 1 + 寿元增加
  - 突破失败 → 跌 1 小境 + 修炼分清零
  - 寿元 < 50 触发 UI signal
  - 寿元 0 触发 DEAD
  - 全员死亡触发 GameOver
