## 19:40 用户反馈"开始新游戏完全玩不了"——根因发现

用户实际启动游戏后**新游戏点了进去主界面但完全没东西/崩**，说我前面的"验收"全是假的。

### 反思

**致命错误**：e2e_smoke 只在 headless 模式跑 service 层逻辑，**根本没真正实例化 UI 场景的 Control 节点**。Godot 4 的 UI 加载是 lazy 的：脚本如有 parse warning-as-error，CharacterService 等 autoload 没问题但 Control 脚本就 fail to load，主界面变空壳。

**根因**：`main_screen.gd:246`：
```gdscript
var msg := {
    "cleared": "...",
    ...
}.get(reason, "✦ 历练结束 ✦")
```
Godot 4 把"变量类型从 Variant 推断"视为 warning，**项目默认 warnings-as-errors**，整个 main_screen.gd 加载失败 → 用户进主界面是个空 Control 没任何脚本。

**修复**：拆 dict 字面量到独立变量并显式标 `var msg: String`。

### 新增 UI 实机验证基建（弥补只跑 service 不跑 UI 的盲点）

1. `scripts/core/ui_probe.gd` + `scenes/ui_probe.tscn`：实例化 main_screen 到 SceneTree（用 add_child.call_deferred 避开 busy 错误），等 3 帧让 @onready 解析，然后通过 emit_signal("pressed") 模拟用户点击：
   - probe 1: 节点解析 - 7 项
   - probe 2-3: 列表填充（5 建筑 / 3 弟子）

   - probe 5: 弟子卡上"入修炼塔"按钮真触发 IN_CULTIVATION
   - probe 6: 出发历练触发 ExpeditionService.active=true / node_count=6
   - probe 7-8: 存读档 / 开门收徒按钮无崩

2. `scripts/core/full_flow_probe.gd` + `scenes/full_flow_probe.tscn`：模拟"双击启动→主菜单→新游戏→主界面"完整链路 9 项 PASS

### 元教训 FFF：headless 跑 service 不等于游戏可玩

**只跑 service 层 e2e 无法发现 UI 脚本 parse error / @onready 解析失败 / signal connect 时序问题**。必须：
- 实例化场景到 SceneTree
- 等帧让 @onready 解析
- 用 emit_signal 模拟点击触发真实回调链

**今后验收流程**：bootstrap_check（service 接口）+ e2e_smoke（service 业务）+ ui_probe（UI 节点）+ full_flow_probe（场景切换）四件套缺一不可。

### 元教训 GGG：Godot 4 字面量推断陷阱

`var x := {literal}.method()` 默认推断为 Variant，warnings-as-errors 项目会**编译失败**。养成习惯：
- `{字面量}.get()` 调用前先 `var d := {literal}; var x: T = d.get()`
- 显式标注返回 Variant 的方法结果类型
