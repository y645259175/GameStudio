## 11:30+ 用户报历练两 bug + 质疑「选项+状态玩法」→ 重做历练事件系统

### 用户反馈
1. 第一个节点(山中隐者)无法继续、撤离也回不去（两截图）
2. "本身功能做得有问题，有没有仔细看策划案那个基于选项和状态的玩法模式，好好研究后大幅修改或推翻重做"

### 根因（两 bug 同根 · UI 死锁）
`expedition_screen._on_continue_pressed` 一点击就 `continue_btn.disabled=true` 并 await 整个 `advance_node_ui`，而事件内首个 `show_text→present_text→_await_continue` 又要玩家点"继续"才能走到 `show_options` → 按钮已禁用 → **死锁**，选项永远弹不出来。撤离后"返回宗门"同样因 continue_btn 一直 disabled 点不动。
**probe 上次用标志位 `_waiting_continue=false` 绕过按钮，所以没抓到** —— 教训：UI 验收必须真 `emit_signal("pressed")` 点击按钮，不能用标志位绕过。

### P0 修复（commit 1c9e4e6）
- `_on_continue_pressed` 改 `_advancing` 重入保护，不再 disable 按钮
- `present_options` 期间才禁用继续(强制选择)，选完恢复；`_await_continue` 确保可点 + `_finished`/退出打断
- `_on_expedition_finished` 置 `_finished` + 恢复 disabled
- expedition_probe 改真点击驱动（检测选项→点可用选项，否则点继续）

### 选项+状态玩法重做（commit f5798c3 + cece9f4）
对照 GDD-03 §2/§3 重做（数据其实本来就符合理念，但缺 DSL）：
- **选项 DSL**：OptionDef 加 cost_stone/cost_time/cost_hp + cond_show/cond_enable/cond_enable_hint + outcome_flag；选项面板水墨化(UITheme.skin_button) + 成本显示(灵石-200) + 不满足置灰+原因 + hover 描述
- **ConditionEvaluator 重写**：realm_at_least/attribute(灵根/五维)/has_resource/expedition_flag/choice/battle_won/disciple_count + 比较运算 >=<=><==!= + &&||。**ctx 必须可选(=null)+全函数 null 守卫**（bootstrap_check 用单参数 evaluate，差点漏掉，回归才抓到）
- **事件引擎**：统一 sync(headless/测试) 与 ui(玩家) 双入口共享 `_build_options/_apply_option_cost/_do_battle`，消除漂移；order+condition 表达三幕
- **EventContext**：加 get_actor()(participant[0] 主角) + expedition_flag(跨事件存 ExpeditionService._exp_flags)
- **内容**：11/13 事件改造三幕剧（叙事→选项→分支后果），含风险/收益、悟性≥70/火灵根≥5门槛、灵石/灵草成本。如山中隐者:请教(悟性门槛)/讨灵草/奉灵石200→大回报
