### 3. 战斗力派生公式（用户原创）

```
战斗力 = 境界参数 × (a×体魄 + b×神识 + 功法战斗力) + 其他战斗力

境界参数 = [1, 2, 4, 8, 16, 32]   # 凡 → 化神
```

### 元教训

#### 教训 A：不要把"修仙小说默认设定"当成"必须有的设计"

我提议加"心性 + 叛门"是因为修仙小说常见，但用户立刻说"不要"。设计纪律：
- **修仙小说的元素不一定都要照搬**——简化设计往往比复杂更好
- 删除一个概念后必须**全文档清理**，不能漏字段 / 漏文档

#### 教训 B：全局规范（如品质 6 级）一旦定下要全文档贯彻

用户把 6 级品质定为**所有可品质对象的统一规范**，意味着未来定丹药 / 装备 / 法宝时都要复用。
落地策略：建 `data/quality/quality_levels.tres` 中央表，各对象引用。

#### 教训 C：派生属性公式比基础属性更重要

战斗力派生公式（境界参数 × 多项相加 × 功法品质 × 功法自身公式）的设计精妙：
- **境界参数指数递增**（1/2/4/8）= 越级 ≥2 倍碾压（修仙世界观）
- **功法品质 × 功法自身公式**= 双系数叠加，给"高品质功法 + 高契合属性"双重激励
- **其他战斗力**= 投放位，dans / 装备 / buff 都能干净叠加

下次设计任何派生属性都参考这种"主乘数 × 加权和 + 投放位"结构。

#### 教训 D：属性扩展性 = Dict + 数据表注册

Character.attributes 用 Dict 而不是固定字段，配 `data/character/attribute_types.tres` 注册——
未来加新属性（M4 加"剑意" / "气运" / "福缘" 等）= 加 1 行表 + 1 个增长系统，**不破坏 Character schema / 不破坏存档**。
这是 §6.7 存档前瞻 + §6.9 解耦的实证。
