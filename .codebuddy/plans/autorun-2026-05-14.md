## 问题记录

### Issue #1 · multi_ball 道具简化为"清屏弹"

**情境**：E3 设计 multi_ball 原本生成 +2 球同时存在
**问题**：当前 ball 是单一节点，碰撞 / HUD / game_over 多处假设单球；改造为多球需重构 ball 集合管理 + 碰撞分别处理 + 球丢失只在最后一球时扣命，工作量超 1 个 sprint
**决策**：multi_ball 改为"立即清除一行随机砖块"作为强力效果（保留差异化），真正多球留 Phase 2
**影响**：autorun 中已记录，sprint-2-plan 已记录，PROJECT.md 已记录
**Phase 2 epic**：E7 多球真正实现

### Issue #2 · GDScript autoload 在 -s 模式下不加载

**情境**：写 test_game_manager.gd 直接引用 GameManager 编译失败
**根因**：godot CLI 的 `-s <script>` 模式下 autoload 不会注册到全局命名空间
**修复**：
1. 测试脚本改为 `preload(...).new()` 实例化
2. powerup_manager.gd 把 `GameManager.add_life()` 改为 `Engine.get_main_loop().root.get_node("GameManager")` 弱引用，去掉编译期硬依赖
**收益**：测试脚本可独立跑；powerup_manager 也变得可单测；符合 refactorer agent 建议的"loose coupling"

### Issue #3 · Godot 4.6 类型推断更严格

**情境**：早期 Sprint 1 末尾出现多个 "Cannot infer the type" 错误
**修复**：用 `absf()` 替代 `abs()`，明确声明类型 `var x: float = ...` 而非 `:=`
**已固化**：写代码后必跑 `--check-only`，已成 SOP

### Issue #4 · UI Label `anchors_preset = 8` 失效

**情境**：用户截图发现 main_menu 文字全部贴在左边，标题被裁切（"CE to Start" / "love Left"）
**根因**：使用 `anchors_preset = 8` (中心锚) + 负 `offset_left/right` 的组合在 Godot 4.6 中可能因 Container 布局解析时 anchor=0.5 但 offset_left=-150 → x = 0.5*viewport - 150，但 horizontal_alignment=1 是基于 Label rect 局部居中 —— 当 Label rect 被 anchor 移到屏幕外（left edge）时，文字也跟着出屏
**修复**：改用 `anchor_left=0, anchor_right=1.0`（占满全宽）+ `horizontal_alignment=1`（在 Label 内居中），让 Label rect 始终覆盖整屏，文字在屏幕中央
**验证**：通过 screenshot_main_menu.gd / screenshot_game.gd 自动渲染截图比对 → 渲染输出正确（标题/HUD/砖块/挡板全部归位）
**收益**：建立了 AI 自主验证 UI 的能力（不再依赖用户手动截图）

### Issue #5 · 用户截图被 IDE 左侧面板裁切（误报）

**情境**：reviewer agent 评审时怀疑"截图左侧裁切"是 viewport 配置问题
**澄清**：用户截图时 IDE 内嵌浏览器的左侧面板覆盖了游戏窗口左 1/5；新跑的 1280x720 截图显示渲染本身完全正确
